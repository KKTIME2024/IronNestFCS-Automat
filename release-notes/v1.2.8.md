## IronNestFCS Smart v1.2.8

### Stable FCS controls across F9 / F9 后控制界面保持稳定

- F9 now reloads only the TaskSystem / Logic layer. The world-space FCS controls stay alive, including the selected shell, Auto Fire and Max Charge state.
- T1-T4 submissions are routed to the current Logic instance at click time, so a stable Host UI cannot retain or call an unloaded Logic object.
- If F9 interrupts marker stabilization, transient T-button input locks are cleared so the submit button does not remain stuck disabled.
- Persistent physical loading continues across F9 as before; the rebuilt TaskSystem replans from the real chamber/loading state.

- F9 现在只重载 TaskSystem / Logic 层。世界空间 FCS 控制界面不会被重建，当前弹种、Auto Fire 和 Max Charge 状态都会保留。
- T1～T4 点击时会路由到当时最新的 Logic 实例，稳定 Host UI 不会持有已经卸载的旧 Logic 对象。
- 如果 F9 恰好打断目标标记稳定采样，会清除 T 按钮的瞬态输入锁，避免按钮一直卡在不可点击状态。
- 实际装填继续保持跨 F9 持久化；新的 TaskSystem 会从真实炮膛 / 装填状态重新规划。

### Internal boundary cleanup / 内部边界整理

- The old mixed-responsibility `FcsSceneInteractor` was split into Host-owned `FcsControlPanel`, reloadable `TargetSubmissionController`, and `PhysicalClickHelper`.
- Planner / Executor now read player control state through the stable Host contract instead of owning UI state inside reloadable Logic.

- 原先职责混杂的 `FcsSceneInteractor` 已拆分为 Host 持有的 `FcsControlPanel`、可重载的 `TargetSubmissionController` 和 `PhysicalClickHelper`。
- Planner / Executor 现在通过稳定 Host 契约读取玩家控制状态，不再让可重载 Logic 自己持有 UI 状态。

### Validation / 验证

- Repeated in-game F9 tests passed while guns were loading, recovering and already loaded; compatible post-F9 missions reused the persistent loading transaction correctly.
- Auto Fire remained enabled across F9 and successfully fired after Logic reload. Max Charge ON/OFF also remained unchanged across F9 and continued to drive C6 / minimum-charge planning as expected.
- Release build passes with no new compile errors.

- 已在装填中、Recovery、LoadedReady 等状态下重复实机测试 F9；F9 后兼容任务能够正确复用持续存在的装填事务。
- Auto Fire 跨 F9 保持开启并能在 Logic 重载后继续自动击发；Max Charge 的 ON/OFF 也会跨 F9 保持，并继续按预期影响 C6 / 最小装药规划。
- Release 构建通过，没有新增编译错误。
