# 协同模式（CO-OP）Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 新增协同模式：自动脚本（雷达）只占用右炮管，左炮管永远留给玩家标点开火。玩家与程序一左一右并行作战，开火序列稳态下自然交替（P→A→P→A）。

**前置依赖（硬依赖，必须先落地）:** `docs/superpowers/plans/2026-08-10-human-machine-collaboration-registry.md`（issue #3a 注册表 + #3b 切割点）：
- `ArtilleryTask.Source`（Auto/Manual）→ `CanUseBarrel` 炮管匹配的唯一依据
- `Registry.Commit`（手动入队即登记）+ `IsHandled` 过滤 PickTarget → 雷达不抢玩家已标目标
- 3b `Canceled` 切割点 → Auto→Coop 时左管自动任务干净让位
- `ClearPendingTasks` 保手动 → 雷达 5s 清队列不冲掉玩家排队任务

**Architecture:** 模式状态机下沉到 `FSC`（`TryDispatch` 需要它做炮管匹配），`FcsModule` 只做编排（雷达启停 / 输入转发 / 面板同步），3D 世界按钮做模式切换（ClickRaycaster 路径），numpad/手柄保留为快捷键。注册表零改动。

**Tech Stack:** .NET 6 / MelonLoader (IL2CPP) / UnityEngine InputSystem。无测试框架（IL2CPP 运行时行为），验证 = 编译 + 运行时清单（见 Task 5）。

## 背景与设计决策（已与仓库主确认）

### 模式矩阵

| 模式 | 雷达 | 雷达占用炮管 | 玩家可用炮管 |
|---|---|---|---|
| AUTO（现状）| 激活 | 双管 | 无（手动开火进共享队列竞争）|
| **CO-OP（新）** | 激活 | **仅右管** | **仅左管** |
| MANUAL | 休眠 | 无 | 双管 |

### 决策表

| 决策点 | 结论 |
|---|---|
| 切换入口 | 3D 世界按钮（AutoFire/MaxCharge 同排，走已验证的 ClickRaycaster）+ Numpad 0 / Ctrl+0 / 手柄 Select 循环 `Auto→Coop→Manual→Auto` |
| numpad 去留 | 保留为快捷键（面板为主，不破坏肌肉记忆）|
| 炮塔竞争 | **排队等待**（不抢占）。每自动循环"击发完成→退膛结束"（~13s）炮塔锁空闲——玩家在这期间开火立即拿到；中途开火最多等一个射循环（~30s），无饥饿 |
| 开火序列 | 稳态 **P→A→P→A 交替**，为锁持有期+槽位释放期的自然涌现行为，无需轮换代码；紧相位偶发双发且自校正；单侧空闲时连续发射属正常 |
| 标记所有权 | **CO-OP 下 `radar.AutoPlaceMarkers = false`**（标记是玩家的操作界面，雷达只在纯 AUTO 模式占用它们；否则每 5s 覆盖玩家标记导致手动标点失效）|
| 面板显示 | `[AUTO]/[COOP]/[MANUAL]`；COOP 下炮管行标 `L:Player` / `R:Auto`（玩家能看出"炮管等炮塔"是正常状态）|
| 手动 4 连发 | 左管严格串行（T1→T2→T3→T4 各 ~60-90s 循环）；玩家嫌慢可切 MANUAL（双管全归玩家）|

### 玩家与程序的双队列语义

- 玩家的手动任务（T1-T4 / Numpad 1-4 / 3D 按钮）入队即 `Registry.Commit`（解析 entityId），雷达 `PickTarget` 跳过已提交目标 → 玩家的 4 连发目标不会被右管抢
- 雷达只给右管派发（OnGunIdle 跳过左管），每次只填右管 1 个槽位
- 玩家的排队任务在雷达 5s 清队列时存活（3a 的保手动语义）
- 切换矩阵：

| 切换 | 左管自动任务 | 右管自动任务 | 手动队列 |
|---|---|---|---|
| AUTO→COOP | 3b 取消/强发 | 继续 | 保留 |
| COOP→AUTO | 玩家任务打完自然交还 | 继续 | 保留 |
| →MANUAL | 3b 处理 | 3b 处理 | 保留 |

```csharp
    /// <summary>当前模式: 默认手动(安全默认)。TryDispatch 按此匹配炮管。</summary>
    public FcsMode Mode { get; private set; } = FcsMode.Manual;

    /// <summary>模式变更事件(FcsModule 做雷达启停, FcsSceneInteractor 刷按钮状态, FcsWindow 刷显示)</summary>
    public event Action<FcsMode>? ModeChanged;

    /// <summary>
    /// 切换模式。调度侧副作用: 清队列(保手动) + 3b 分流——
    /// 失去自动接管权的炮管上的自动任务: 未装填→取消(不碰炮膛), 已装填→forceFire(防卡膛)。
    /// </summary>
    public FcsMode SetMode(FcsMode next)
    {
        ClearPendingTasks();   // 保手动队列(3a)
        if (next == FcsMode.Manual)
        {
            CancelOrForceFire(LeftTask);
            CancelOrForceFire(RightTask);
        }
        else if (next == FcsMode.Coop)
        {
            CancelOrForceFire(LeftTask);   // 左管让位给玩家
        }
        Mode = next;
        ModeChanged?.Invoke(Mode);
        return Mode;
    }

    private static void CancelOrForceFire(ArtilleryTask? task)
    {
        if (task == null || task.Source != TaskSource.Auto) return;
        if (task.progress < Progress.LoadingBullet) task.Canceled = true;
        else task.forceFire = true;
    }
```

- [ ] **Step 3: TryDispatch 重构——CanUseBarrel 炮管匹配**

`TryDispatch` 替换为"找第一个有可用炮管的任务"（保持其余队列顺序）：

```csharp
    /// <summary>任务能否使用指定炮管: 协同模式下手动任务只去左管, 自动任务只去右管; 其余模式任意。</summary>
    private bool CanUseBarrel(ArtilleryTask task, LeftRight barrel)
    {
        if (Mode == FcsMode.Coop)
            return barrel == LeftRight.Right ? task.Source == TaskSource.Auto : task.Source == TaskSource.Manual;
        return true;
    }

    private void TryDispatch() {
        while (_taskQueue.Count > 0) {
            // 找第一个有可用炮管的任务(协同模式下玩家/自动任务按炮管分流)
            ArtilleryTask? chosen = null;
            LeftRight slot = LeftRight.Left;
            foreach (var task in _taskQueue) {
                if (LeftTask == null && CanUseBarrel(task, LeftRight.Left)) { chosen = task; slot = LeftRight.Left; break; }
                if (RightTask == null && CanUseBarrel(task, LeftRight.Right)) { chosen = task; slot = LeftRight.Right; break; }
            }
            if (chosen == null) break;

            // 从队列移除 chosen, 其余保持顺序
            var rebuilt = _taskQueue.Where(t => !ReferenceEquals(t, chosen)).ToArray();
            _taskQueue.Clear();
            foreach (var t in rebuilt) _taskQueue.Enqueue(t);

            if (slot == LeftRight.Left) LeftTask = chosen;
            else RightTask = chosen;
            Registry.Commit(chosen);   // 手动任务幂等(入队已登记)
            StartTaskRoutine(slot, chosen);
        }
    }
```

## 风险与已知事项

- **硬依赖**：注册表/3b 计划必须先落地（Source/Registry/Canceled/保手动清队列），本计划在其后执行。
- **AutoPlaceMarkers 门控是正确性关键**：若漏掉，COOP 下雷达每 5s 覆盖玩家标记，手动标点失效。
- **交替是涌现行为**：由锁持有期 + 槽位释放期（13s）自然产生，非设计保证；紧相位偶发双发属预期，自校正。
- **左管空闲 = 火力量减半**：COOP 下玩家 AFK 时自动只有单管火力，为"永远留一管给玩家"的契约代价。
- **模式复位**：热重载后 Mode 复位 MANUAL（安全默认）。
- **下一步可选增强**：若实测玩家等炮塔 >30s 频繁，升级为 3b 抢占（取消未装填自动任务）——本计划默认不做。
