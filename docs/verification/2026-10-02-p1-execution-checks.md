## 2026-10-02 实机失败与修正

`MelonLoader/Latest.log` 在 17:50:51 已记录 30 个敌方目标，随后进入自动模式却没有派发。上一版将所有新实例的 `UnobservedFlightPossible` 都初始化为 true，使正常开局也无法恢复；控制台绑定后的 `RecoveryPending` 没有自动回读解除。自动任务击发还依赖独立的默认关闭 Auto Fire 开关。

修正：宿主区分新场景与同场景热重载；正常开局不要求现场问卷，切自动后读取实物并执行必要的解除武装恢复；自动任务按自己的执行授权进入击发，手动任务仍保留独立 Auto Fire 控制。热重载缺失在飞历史时继续暂缓，不跨重载重放旧队列。默认面板仅模式、左右炮状态和队列，取消及退弹操作在展开区；实际恢复阻塞才显示对应入口。

新增回归直接链接宿主 `ReloadFlightState`，覆盖首次加载、新场景、同场景重载及失败后重试，防止再次把正常开局误判成未知在飞。修复后的炮响和机械行为仍待实机验证。

## 本轮实现

第二次实机反馈仍失败：18:26:47 日志记录 35 个敌方目标，进入自动模式后没有派发。已继续修正源码：武装检查改读实际 `ArmedFireRelayOneShot.IsLeftArmed/IsRightArmed`，不再以臂杆父对象的硬编码角度判定；装药改读膛内 `ShellBlueprint.currentPowderCharge`；初始化失败的实例不产生重载在飞历史，场景绑定失败自动重试并忽略旧场景迟到回调；派发阻塞输出膛内、机构、武装恢复及暂停状态。

| 项目 | 行为 | 主要文件 |
|---|---|---|
| 资源所有权 | 炮位、采购台和炮塔按占用身份释放；旧回调不能释放后继持有者；运行中看门狗不强制重置共享锁 | `ExecutionLeaseLedger.cs`、`CoroutineLock.cs`、`FSC.cs` |
| 子动作与取消 | 单个驱动器展开嵌套协程；撤销未提交射击的任务后不追加采购、选药或武装；已提交扳机继续观察真实结果 | `CancellableRoutine.cs`、`FSC.cs` |
| 按钮收尾 | 武装、确认、采购按钮和计算器在停止时执行松开；延迟界面回调登记并在卸载时停止 | `TriggerConsole.cs`、`FcsSceneInteractor.cs`、`BallisticCalculator.cs` |
| 炮位交接 | 子动作收束、实物武装 OFF、机构可接任务且无待退膛状态，才交给后续任务；无法确认则保留隔离 | `FSC.cs`、`GunSystem.cs` |
| 保留弹药 | 不兼容弹优先让另一管接任务；双管不兼容则排队等待；不通过隐式退弹或手动指定弹种回退推进 | `FSC.cs` |
| 明确退弹 | 面板两次确认后请求退弹；提示可能损失弹药；结束后复核空膛和机构静止，失败保留隔离并允许重新请求 | `FSC.cs`、`FcsWindow.cs` |
| 暂停与恢复 | 暂停保留计划及目标占用；恢复复核实体存活和位置；旧修订、死亡及消失目标不重新授权 | `PausedTaskRecovery.cs`、`TacticalRadar.cs` |
| 取消排除 | 明确取消单体或固定成员后自动选择排除；显式恢复或观测到旧 ID 消失后解除；策略清队列不产生排除 | `AutomaticTargetExclusions.cs`、`FcsModule.cs` |
| 同场景热重载 | 宿主仅交接排除 ID 值数据，场景切换清除；旧队列不重放；新逻辑默认暂缓并提示未登记在飞炮弹可能存在 | `IFcsSessionState.cs`、`LogicReloader.cs`、`FcsHostMod.cs`、`FSC.cs` |

## 实机操作与通过条件

更新宿主和 Abstractions 后重启游戏；仅 F9 更新 Logic 不会加载新宿主。新场景中切换 AUTO 即请求运行，系统读取实物状态后派发；无需现场确认问卷。同场景热重载缺失在飞历史时仍暂缓，并仅在这个状态提供确认恢复入口。

| 设计场景 | 操作 | 通过条件 | 当前证据 |
|---|---|---|---|
| C01 | 选弹、推弹、选药、推药、合栓和武装期间分别暂停/取消 | 不追加动作、不强发；保留弹药或明确隔离；恢复不重复推药 | 离线路径检查；实机待验 |
| C02 | 左管武装后取消，再命令右管单发 | 左管解除武装回读确认前不自动拉全局扳机；左管不带响 | 实机待验 |
| C03 | 扳机提交至出膛之间取消 | 保留待确认观察；确认出膛或未知；没有第二次扳机提交 | 状态回归通过；实机待验 |
| C04 | 留下同弹/不匹配弹和装药，再命令新任务 | 兼容才复用；不兼容选另一管或等待明确退弹 | 代码检查；实机待验 |

| C07 | 鼠标操作原作机构后再选择继续 | 自动授权撤回；按实物重新检查；不与玩家持续争抢控件 | 实机待验；检测边界见下 |

## 验收边界

- 武装 OFF/ON 姿态阈值、`pendingReload` 的出膛含义及选药字段与实际装药的关系仍需当前版本实测。就绪检查不构成这些机制已验证的证据。
- 鼠标接管检测依赖屏幕射线和控件祖先名称；手柄、拖拽、脚本改动或未匹配控件不能宣称已全面覆盖。无法可靠捕获的操作，应先显式暂停；击发前仍执行实物闸门。
- 尚无可靠目标实例序号。若同一字符串 ID 在两次观测间直接换实例，排除继续保守保留；展开操作区提供显式恢复选择。
- 在飞记录尚未跨重载完整交接；采用设计允许的“可能存在未确认在飞炮弹”降级。现场确认来自玩家，不能承诺首发或严格落地顺序自动得到证明。

P1 的实机验收通过之前，不将这些检查标记为阶段完成，也不据此开启 P2 的严格时序承诺。
