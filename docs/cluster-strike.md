# 弹种集群打击：HE/HCHE 收益分析 + 注册表深化（设计）

> 状态：**已实现（2026-08-12，`24deb8a`，未编译未测试）**。分支 `feature/next`。
> **剩余决策（星标权重/优先级重构/CBT）待进游戏实战观察后定，本设计不含。**
> 前置依赖：ToF 射表（`ToFTable`）、注册表（`TargetRegistry`）、统一瞄准路径（已实现）。
> 验证清单见 `docs/daily/2026-08-12.md` §4。

## 1. 目标

把"点对点打击"升级为"按毁伤半径集群打击"：当目标本应打 HE 时，若其周围存在可被一发爆炸连带的软目标，则**搜索最优落点、换 HE/HCHE 集群一发多杀**，省弹药点数。注册表位置提交随之深化（按毁伤半径覆盖）。

## 2. 动机

- 现在 `ChooseShellType` 只按"装甲/地下 → AP，否则 → HE"，永远瞄准单个 entityId——**弹种有毁伤半径，但从不利用 AoE**
- 游戏弹药成本：AP 10 / HE 10 / HCHE 18（正式版价格）；毁伤半径（维基）：AP 0.14 / HE 0.27 / HCHE 0.63 km
- 一发 HE(10点) 清 2+ 软目标，比逐个打（10点×N）省；HCHE(18点) 清大簇同理

## 3. 已锁定决策

| 决策 | 结论 |
|---|---|
| 作用域 | **仅自动模式 + 软目标**；选择流程（优先级 6 档 + 距离/方位排序）**零改动**；装甲/地下 → AP 原样；手动/移动目标不动 |
| 改动点 | 唯一新增：软目标"本应打 HE"时，先做集群收益分析 |
| 弹数据源 | **维基静态表**（不读 `ShellEffectRule` 反射）：AP 0.14/10、HE 0.27/10、HCHE 0.63/18 |
| 集群几何 | 直径(2R)搜索 + 最大可覆盖子集 + **MEC 圆心为落点** |
| HE/HCHE 决策 | 见 §4.2 |
| 注册表深化 | **全弹种击发后注册爆区**：落点 + 该弹毁伤半径，`IsHandledNear` 按它覆盖——单点 AP/HE/HCHE 与集群任务一律注册，防爆区内重复开火 |
| **友军禁区** | 集群落点 **R 内不能有友军**——有则弃用该落点，降级取次优子集 |
| 优先级/价值模型 | **延期**（星标斜率难校准，等实战） |

## 4. 核心语义

### 4.1 集群几何（已锁定）

```
必须杀选中的软目标 T（位置 P）:
  可行落点 P' 满足 |P'−P| ≤ R          // 落点可在 T 的 R 圆内偏移
  邻居 X 可同杀 iff |P'−X| ≤ R
  → 候选搜索判据: |X−P| ≤ 2R          // 直径（落点偏移自由度）
```

```
对 T:
  1. 搜索集 C = {T} ∪ {未处理软 X : |X−T| ≤ 2R}
  2. 求最大子集 S ⊆ C, T ∈ S, 且 S 的最小覆盖圆(MEC)半径 ≤ R
  3. 发射点 = S 的 MEC 圆心（全员离落点 ≤ R → 全被炸到, 且含 T）
     约束: 圆心 R 内不能有友军 —— 有则弃用该落点, 降级取次优子集(或单点)
```

> at-member / 中点都不够——最优落点是"最大可覆盖组"的 MEC 圆心，不一定落在任何成员或中点上。小候选集（|C| 通常 2-6）下枚举含 T 子集 + 算 MEC 可行。
> **友军禁区**：候选落点必须 `无友军离圆心 ≤ R`。友军数据 = 雷达读 `RoleAlly` 实体世界坐标（当前雷达只收敌，需新增暴露）。此约束同样应适用于单点 HE/HCHE（现有代码不查友军——潜在缺口，是否一并修待实战确认）。

### 4.2 HE/HCHE 收益决策

```
N_he,   落点_he    = 用 HE  (R=0.27, 搜索 2R=0.54) 求最大覆盖子集
N_hche, 落点_hche  = 用 HCHE(R=0.63, 搜索 2R=1.26) 求最大覆盖子集

N_he ≥ 2       → HE   @ 落点_he    (10点, 清 N_he)
elif N_hche ≥ 2 → HCHE @ 落点_hche (18点, 清 N_hche)
else            → 单点 HE @ T       (原行为)
```

> N_he ≥ 2 = 同价升级（HE 比单点贵一样，清更多）；N_hche = HCHE 溢价 1.8×，需 ≥2 个且 HE 覆盖不够时才值。效率数值（≥1.8 阈值）留实战调。
> **两路候选落点都必须过友军禁区检查**（§4.1 约束），有友军的落点不算进 N_he/N_hche。

### 4.3 注册表深化（全弹种爆区注册）

```
每发 AP/HE/HCHE 击发时（task.Fired）:
  在落点(瞄准点)注册 blastRadius = 该弹毁伤半径 的位置覆盖
IsHandledNear(pos, r) → 距离 ≤ r + commit.blastRadius 即覆盖
→ 雷达 PickTarget 跳过任何在爆区内的未处理目标（不管它是单点还是集群打的）
```

- **集群任务**：落点 = MEC 圆心，blastRadius = 所选弹 R（覆盖整个集群区域）
- **单点任务**：落点 = 目标位置（或移动提前点），blastRadius = 该弹 R——AP(0.14) 也能带掉贴脸邻居，HE(0.27) 同理
- **防爆区重复开火**：一发 HE 会炸死 T 周围 0.27 内邻居 → 邻居被覆盖 → 雷达不重复补发（省弹核心收益）
- 生命周期 = 飞行窗口（与现有 position-commit 过期一致；打偏后窗口到期恢复可拣）
- 与 entityId 防双发并存：单点用 entityId 路径锁 T 自己，爆区用位置路径锁邻居——两条路径互不冲突

## 5. 明确延期（待进游戏实战）

- **星标/RC 价值权重**：价值函数（`1 + stars + ...`）的星标斜率难校准，暂不进入排序
- **优先级重构**：现有 6/5/4/3/2/1 档保留（含 FDC/火炮/弹药/工事类型档），不推倒
- **CBT 反炮兵**：FDC 生存加成、关卡分类（有/无 FDC+火炮）、CBT 剩余秒数——全部延期（CBT 暂只读到"有无 timer"）
- **价值 vs 效率权衡**：星标 FDC 会排在软集群后吗？——本设计不改变排序，故不发生；价值模型加入后需重审
- **ShellEffectRule/ShellSpeed 反射**：暂用维基静态表；将来读实时属性可细化 ToF（初速维度）
