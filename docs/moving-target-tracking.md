# 移动目标跟踪：方案对比与数据核对（讨论中）

> 状态：设计讨论中，未定方案、未实现。本文档记录当前瞄准数据来源、关键发现、两个候选方案与待验证项，供讨论对表。

## 1. 目标

识别移动目标后装填，开火前用 ToF + 距离解算 + 射表**实时修正仰角/方向机直到发射**。

现状：移动目标按解算时刻的静态位置瞄准，装填 ~70s 后解算早已过期，打移动目标靠蒙。

## 2. 当前瞄准数据来源

| 数据 | 来源 | 备注 |
|---|---|---|
| 仰角 | 游戏内弹道计算器 | 驱动拨盘 → `Calculate()` → 读 `OdometerDisplay`，~0.5s×5 步/次 |
| 方位角 | mod 自算 | `CalcAngle`：turret→目标 SignedAngle（地图几何） |
| 距离 | mod 自算 | 世界坐标 ×3.8164 → km |
| 装药档 | mod 策略 | `MinimumCharge(dist)` |
| 弹种 | mod 策略 | `ChooseShellType` |
| ToF | mod 射表 | `ToFTable`（ToF.txt 实测），仅显示/倒计时用 |

## 3. 关键发现

### 3.1 弹道定律是线性的（两独立来源交叉验证）

社区 FCC 公式 `仰角 = 0.012 × 距离(m) ÷ 装药` 与 ToF.txt 仰角列**全部格子**精确一致（抽查：5km 装药2 = 30°、16km 装药5 = 38.4°、20km 装药6 = 40°，全对）。

- → 仰角可一行公式直算，无需驱动游戏计算器，实时修正零计算开销
- 装药有效边界：仰角 ≤ 60°（最大仰角）→ `装药 ≥ 距离(km) × 0.2`（即"每 5km 一包药"，与现有 `MinimumCharge` 分段吻合）

### 3.2 FCC 项目不可引入

`github.com/JoeOakley52/UNOFFICIAL-Iron-Nest-FCC`：
- 无许可证（unlicensed），搬代码有法律风险
- 唯一内容 = 仰角线性公式（我们已独立推导）+ ToF **手动输入框**（无公式无数据）
- 结论：零额外数据价值，方案 2 全程自研

### 3.3 ToF 现状

- 仅我们的射表（装药 × 射程二维），**无弹种维度**
- 覆盖 3–20km，越界夹紧；数据手工录入未复核（待构建机抽查）

## 4. 两个方案

### 方案 1：算一次 + 掐钟发射（尊重原版玩法）

- 装填完成后解算一次提前量，命中点 = 目标在 `(击发 + ToF)` 的位置；等待时钟对齐发射
- 优点：沿用游戏计算器，无外部模型；ToF 射表正好提供"掐钟"数据
- 缺点：预测窗口 = 装填(~70s) + ToF，目标机动即失效；有等待浪费
- 变体：
  - **(a)** 装填完、击发前**再解算一次**（命中点=击发+ToF，随即发射）——简单，多一次计算器驱动（~3s）
  - **(b)** 提前算更远命中点 T，装填完**等时钟**到 `(T − ToF)` 再发——用等待吸收装填时长不确定性，但预测窗口更长、更怕机动

### 方案 2：外部解算 + 实时修正（装好即发）

每帧求解器（`(P0,V)` 创建时冻结，t 相对创建时刻）：
```
提前点 P = P0 + V×(t + ToF(dist))     ← 闭合式, 无需迭代（匀速假设）
方位角   = CalcAngle(P)                ← 每帧写 DesiredRotation（非阻塞）
仰角     = 0.012 × dist_m ÷ 装药       ← 装药装填时定格, 每帧写仰角杆
击发     = 装填就绪即发，无需等钟
```

- 优点：预测窗口仅 ToF（不再是 70s+ToF）；装好即发；方位/仰角全程修正
- 风险/待验证：
  - ~~直接设仰角杆、跳过游戏计算器需实测~~ → **已确认允许**（2026-08-12）
  - 0.012 系数来自当前版本社区+自测，需游戏内复核
  - 装药档在 5km 边界附近（目标距离摆动）跳变导致解算不连续，需钳制策略

## 5. 方位角分析

- 现在：`CalcAngle` 静态算一次；`Turret.SetRotation` **阻塞等待**转完（`rotationVelocity == 0`）
- 移动目标：需每帧更新 `DesiredRotation`（非阻塞版），追提前方位角
- 可行性：方向机 3.36°/s（84→0°=25s 实测）≫ 常规目标角速率（10km 0.05km/s → 0.29°/s；5km 0.1km/s → 1.15°/s）→ 追得上

## 7. 方案 2 详细设计与生命周期（主选；方案 1 变体 A 为退路）

> **已定决策（2026-08-12）**：主选方案 2 直接实施（原版手操、容错高）。**统一路径**：所有任务走公式 + 连续瞄准（静态任务速度=0 自然退化）；**跳过游戏计算器已确认允许**（直接设仰角杆，无需探针）。计算器**纯装饰视觉同步**：每发装填期并行拉一次（静态目标正确数据、移动目标大致数据，不回传、不参与瞄准），从串行流程移出、与装填并行。**手动模式一律按静态目标处理**（`IsMoving=false`）。变体 A 仅作退化回退。

### 7.1 组件

| 组件 | 职责 |
|---|---|
| `TargetLeadSolver`（新，纯数学） | 匀速目标解析瞄准函数 `aim(t)`，输出方位/距离/装药/仰角 |
| 弹道公式 | 仰角 = `0.012 × dist_m ÷ 装药`；装药 = `ceil(dist_km × 0.2)` |
| 非阻塞机构驱动 | 每帧写 `DesiredRotation` + 仰角杆，替代阻塞 `SetRotation`/`SetElevation` |

### 7.2 瞄准函数（解析闭合式）

```
P_t(t)  = P0 + V·t
aim(t)  = P0 + V·(t + ToF(t))            // t = 候选击发时刻
ToF(t)  = ToFTable(dist(P0 + V·t))       // V 小，忽略 V·ToF 项，无需迭代
bearing = CalcAngle(aim(t))
dist    = |aim(t) − turret|
charge  = ceil(dist_km × 0.2)
elev    = 0.012 × dist_m ÷ charge
```

每帧把 t 代入 → 写两个 setpoint。`P0` 为任务创建时冻结快照、`t` 为相对创建时刻的偏移——匀速假设下闭合式自洽，**无需实时查雷达**（非匀速敌人证实后再加实时查询）。误差物理下限 = 目标加速度 × ToF。

### 7.3 任务生命周期

> 关键约束（来自 `WaitForReloadReady`）：**装填要求仰角静止**（`elevationChangeVelocity == 0`），**但不检查炮塔转动** → 装填期只能追方位、不能追仰角。

| 阶段 | 动作 | 约束 |
|---|---|---|
| 1 识别 | 雷达标移动目标（`IsMoving` + `Velocity`，**仅自动模式**）；手动任务一律静态 | — |
| 2 创建 | 装药按**全程预测最远距离 + 余量**选（装填后不可改）；弹种照旧 | 见 7.4 |
| 3 解算（替代+并行） | 不用游戏计算器；`TargetLeadSolver` 初始化 aim；**计算器视觉同步协程与装填并行**（纯装饰，静态正确/移动大致，不回传） | desk 锁不再被解算占用；视觉同步单发短持有 |
| 4 装填 | 弹+药装填；**炮塔追 aim(t) 方位**（允许），**仰角静止** | `WaitForReloadReady` |
| 5 仰角跟踪窗 | 装填完成后：仰角杆连续追 aim(t) 仰角，炮塔继续追 | 就绪判定：双机构误差 < 容差 且 `CanFire` |
| 6 确认+击发 | 5 步确认 + Arm + Fire；期间继续跟踪，Fire 瞬间取当前 aim | 击发后 `Fired/InFlight/Registry` 不变 |
| 7 飞行/落点 | 倒计时（已实现） | — |
| 8 退化 | 目标出射程 / 装药不足 / 速度丢失 → 中止或落回变体 A | — |

**时序要点**：仰角跟踪只能从装填完成后开始（游戏约束）→ 仰角摆到提前角（0→60° ≤32s）与确认（~1-2s）期间 `aim(t)` 持续漂移，机构追着走；机构转速（高低机 1.875°/s）≫ 目标诱导的仰角漂移率 → 收敛、误差小。这个窗口与变体 A 的窗口相同，但方案 2 每帧重算到击发瞬间，误差 = 机构滞后 + 加速度×ToF，**严格优于**变体 A 的"单次复算后整窗漂移"。

### 7.4 装药档边界（"每 5km 一包药"）

- 装药在装填时定格，必须覆盖**全程预测最远距离**：`charge = ceil((dist_lead_max + margin) × 0.2)`
- 目标加速逃离超出覆盖 → 退化路径（中止或变体 A）
- 高装药 = 更平弹道 + 更短 ToF（射表）→ 对移动目标反而有利（缩短预测窗口）

### 7.5 与现有系统交互

- **desk 锁**：解算不再占用 → 锁只剩装药/炮弹采购 + **每发一次计算器视觉同步**（装填期单发驱动，无速率限制、无连续噪声、不饿死另一门炮）→ 两门炮"抢占"问题消失（结构收益）
- **turret 锁**：跟踪期仍独占（一台炮塔，天然如此）
- **Registry / InFlight**：不变
- **确认序列**：保留（游戏要求），aim 已在跟踪，仅需 ~1-2s
